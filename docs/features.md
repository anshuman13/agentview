# Features

## Layout

- **Task box** (right): prompt, mode and model menus, context meter, and the timeline below it. A More menu at the
  right of its header holds Agents (the chat's subagents), what is waiting elsewhere, usage, the Mac name and advisor counts. ⌥⌘B hides it
- **Editor** (center): File tab follows Claude's edits and shows the diff against HEAD, inline or side by side (the split button in the file bar, remembered per browser: last commit on the left, the file on the right, lines aligned with blank rows). Markdown files open as a rendered document with an outline, and the preview button shows the source. In the rendered document each top-level block has a pencil (on hover, or after a tap on touch) that swaps it for a Markdown box with Save (Cmd+Enter) and Cancel (Esc); Save writes only that block back and refuses when the file changed under it. Selecting text shows an Ask Claude button that opens a "What should change?" field and sends the quoted passage with the path to the chat (`docAskPrompt` in `shared/docEdit.ts`). Saving works for project files and for Markdown files in any work folder. A Markdown file the agent writes or edits (other than a Claude memory file, which stays in the work fold for its Remembered chip) gets a doc card in the chat (the latest one per file stays visible outside the work fold, "Updating…" while the edit runs) that opens it here. On Android the doc card opens the file in a sheet, and the rendered file is split into blocks at blank lines (a fenced code block stays whole, `docBlocks` in `workspace/DocEdit.kt`); a long press on a block offers Ask Claude (a sheet with the block and a "What should change?" field) and Edit (an inline field with Save and Cancel), both disabled in read-only mode. CSV and TSV files open as a table (delimiter sniffed from the first line, sticky header and row numbers, a Filter rows field, click a header to sort, first 1000 rows drawn); the table button shows the raw text. In chat replies, a file path in inline code or a link (absolute, `~/` or relative to the chat's folder, with an optional `:line`) opens in this pane, from any folder; relative paths need a folder part unless they are `.md` or `.csv`. On Android the same paths in a chat's replies show in the link colour and open the file in a sheet at that line (`filePath` in `ui/FilePath.kt`, checked by `shared/fixtures/file-path.json`); a link target is URL-decoded first on both clients, so `docs/My%20notes.md` opens the file; Markdown outside a chat leaves them plain. In the diff, a long press or a right click on a line quotes it into the composer as `path:line`; on a changed block the same gesture opens a menu with Quote line and Revert this change, which asks first and then saves the file with that block put back to the last commit (not offered for new or binary files). The pencil in the file bar turns the file into an editor; Save or Cmd+S writes it back (project files only, never inside credential folders). Gitignored `.env` files show in the explorer without the eye toggle. Browser tab shows your Chrome. Observe, Deploy and MCP open as further tabs here
- **Sidebar** (⌘B): Explorer, Source Control, GitHub Pull Requests, Sessions (open and recent chats; one bar holds the search box and a New session in a repo button that opens the New chat sheet) and Workspace (repos, chats, Paseo worktrees). In Workspace a repo with no live chat starts folded to its header, and a repo shows its 5 latest chats with Show all N (Show less when open). The search box in both views finds chats by every word of the query across title, saved title, first prompt, summary, branch and repo (`chatMatches`, on web and phone alike; Pinned and Needs you use it too)
- **Status chips** (phone only): the chips (Running, Needs you, Done) are only on a repo's page, with Mark all read after Done; the main Sessions page has just the Work and Personal chips, and its More menu starts with Mark all read while the segment has Done chats
- **Chat rows** (Sessions view: Pinned, Needs you, repo groups, Recent): a title and one meta line (repo, the branch when it is not the default, the short model of a live chat such as "Opus 4.8", then, for a Needs you chat, what its first request asks (Question, Plan approval or Permission: Bash), else the Running status, "No activity for 15 min" or the time since last activity such as "3h ago" or "yesterday", then the +/- counts of a finished chat; a chat with a pull request shows "#123" and, for the open chat's repo, a dot for its checks that opens the pull request on GitHub; the phone shows the number as text in the same line). Rows are not indented under their repo, are always two lines high (a one-line title and a one-line meta, ellipsis on both, on web and phone) and carry no badge: a dot before the title shows the state (amber Needs you, red Failed, pulsing Running, or the accent unread dot for Done, with that word as its label), and a bold title marks Done and Needs you chats. Failed means the last turn errored, cleared when the next turn starts; Done is activity since you last opened the chat. The state slot at the end holds one item: the run tag when the chat has a run that does not need you, else the bell-slash icon of a muted chat; a run that needs you shows only as the Needs you dot. A chat you did not rename whose first prompt starts with @mentions is titled by its first line without them (the next non-empty line, then "About store.ts" for a file or "Follow-up chat" for a chat), at most 80 characters. A repo group header is one line: the repo name, at most one count badge (Needs you, else running, else unread) and New chat; a chat starting in a collapsed group opens it for 8 seconds without changing the saved collapse state. The time you last opened each chat is kept in `~/.agentview/seen.json`, so opening a chat clears its Done badge on every device; a chat with no entry is never Done. The Sessions tab dot and the sidebar count cover open chats other than the one you are viewing that are Done or Need you, plus attention items. Repo groups list a group with a Needs you chat first, then the rest by latest activity, and the order holds until the tab is shown again (web) or the Sessions screen opens or its search, segment or status changes (phone), except that Needs you groups still move to the top; rows inside a group hold too, and a new chat shows first. Chat rows take keys: j / k or arrows move between rows and Enter opens one, and ⇧⌘] / ⇧⌘[ (Ctrl+Shift off Mac) view the next or previous open chat in row order, wrapping, and ⌥⇧↓ / ⌥⇧↑ view the next or previous open chat that is Done or Needs you (Slack's jump to unread; "No unread chats" when there is none). One More button opens a menu: Resume (a stalled chat that has not failed; it opens the chat, stops the hung turn and sends "continue"), Retry (Failed chats), Pin or Unpin, Mark as unread (a saved chat with no state that you are not viewing; it stores 0 as the seen time, so it shows Done until opened; the phone row menu has it too), Mute or Unmute (Slack's mute: no "Claude finished" browser notification for that chat, Needs you still notifies; kept per browser, and the phone row menu has the same Mute for its notifications; a muted row shows a bell-slash icon), Copy link (`<origin>/?session=<id>`, on the phone too), Rename, Open beside (desktop), Close chat (open chats), Archive. Retry opens the chat and resends its last prompt as a new prompt. In the open chat, while it is idle and Failed, the end of the transcript shows "Claude stopped: <the error's first line>" (the provider's name) with a Retry button that does the same; the line goes when the next turn starts, and the phone hides it in read-only mode. While a chat is stalled and not Failed, the open chat offers Resume, which stops the hung turn and sends "continue" once (a steer): on web a "No activity for 15 min" line with a Resume button at the end of the transcript, on the phone a Resume button above the composer. Open beside shows that chat in a second column with its own composer (`?beside=<chat id>` does the same); the arrow in its header moves it to the main column. Rename edits the title in place (Enter or leaving saves, Esc cancels); a double click on a chat title (desktop) or a long press on the row (phone) starts the same edit; a long press on a chat row renames and does not open the menu. The rename is written to the transcript, so it survives reload. Running agents show in the open chat's Agents pane, not under the chat row. Archive always moves the chat to the bin, whatever its age, and the bin keeps it for 7 days. Once an hour (and a minute after the server starts) the server archives every chat idle for 2 days (`ARCHIVE_MS`), skipping pinned chats and open chats that are running or wait on you; an idle open chat is closed first (`server/src/agent/claude/autoArchive.ts`)
- **Bin**: the web Sessions view and the end of the phone Sessions list (not on a repo page or while searching) show a folded Bin header with the count and an Empty bin button that asks first ("Empty the bin?", N chats, the transcripts are removed permanently). Open, each archived chat shows its title ("Untitled" without one), "<repo> · 6d left" (hours under a day, such as "23h left"), a Restore button that puts it back in its repo group ("Chat restored") and Delete for good, which asks first ("Delete this chat?", the transcript is removed permanently); on the phone Delete for good is in the row's menu with Restore. On the phone the Bin also shows under the empty Sessions page ("No work chats yet"). The section is absent with an empty bin, and the phone hides Restore, Delete for good and Empty bin in read-only mode. The hours left are `binLeft` in `web/src/sessions/folders.ts` with `shared/fixtures/bin-left.json`, mirrored in `sessions/Folders.kt`
- **Spec tasks**: a rendered Markdown file under `.claude/specs/` or `.kiro/specs/` with `- [ ]` or `- [x]` lines (web editor and the phone file view) gets a Tasks header with an "N of M done" badge (plus "· 1 in progress" when a task is marked). Each open task has a Start button, or an "In progress" badge when its line ends with ` (in progress)`. Start sends "Do task <n> in <path>: <text>. While you work, append " (in progress)" to its line. When done, tick its box and remove that suffix in one edit before moving on." to the chat, queued while Claude runs. The spec prefix of "Start with a spec" carries the rule too, so Claude ticks each box right after finishing the task. The counts follow the file as boxes are ticked (the web editor reloads on `file_changed`, and the phone file view reloads the open file on the same event), and the phone buttons are disabled in read-only mode. The parser is `shared/specTasks.ts` with `shared/fixtures/spec-tasks.json`, mirrored in `workspace/FilesLogic.kt`
- **Start with a spec**: the palette command "Chat: Start with a spec" sets plan mode and fills the composer with a prefix that asks for `.claude/specs/<slug>.md` (numbered, testable Requirements, Design, and Tasks as `- [ ]` lines) and a stop for review without code changes; it does not send. The text is `specPrompt` in `shared/specTasks.ts` with `shared/fixtures/spec-prompt.json`, mirrored in `workspace/FilesLogic.kt`. `/spec-review <path>` (a session command in the slash menu, `specReviewPrompt` in `shared/specTasks.ts`) has the agent start two subagents that see only the spec, one reading it cold and listing what it had to guess, one checking the paths, names, routes and test commands it names against the repo
- **Chat transcript**: opening a chat sends its last 150 events; the rest is paged in on demand. The Show earlier row at the top reads "Show earlier (N hidden)"; tapping reveals rows the window hides, then loads 150 older events ("Loading earlier" while it runs, taps ignored) and keeps the scroll on the same row. A chat that opens with fewer than 3 replies loads earlier pages by itself, up to 3 pages, and stays at the bottom; a failed page is not retried by itself. The last 30 rows paint first and the rest follow in steps of 30 with the scroll held, and settled replies keep their rendered markdown so a revisit does not parse them again. The last 150 events of the 8 most recently viewed chats are kept, so switching back shows them at once while the server's init is on its way. The row is gone at the start of the held history, and a failed load shows a notice and leaves the row for a retry. A prompt you sent that needs more than 6 lines at the current width shows 6 lines with Show more / Show less under it (web keeps an opened prompt open across reloads, the phone across rotation); images and the queued bubble never fold.
- **Pinned chats**: Pin on a chat row's menu in the Sessions view keeps that chat in a Pinned group above the repos (newest pin first, also shown in Needs you while waiting). Pins are stored on the Mac in `~/.agentview/pins.json`, so every device sees them after its next reconnect or reload; deleting, archiving or binning a chat drops its pin
- **Codex** (top of the activity bar): Search, Overview, Tasks, Meetings, Wiki, Jobs and Goals, filtered by work or personal
  profile; see [Codex](#codex)
- **Terminal** (bottom, ⌘J): a shell in the chat's folder
- **Share to the app (Android)**: text or a link shared into AgentView asks "Add as task" (saved to Tasks, with a time read from the text), "Send to chat" (appended to the composer), or, when a meeting is running or starts within 15 minutes, "Add to meeting notes" (a time-stamped line in that meeting's notes).
- **Command palette** (⇧⌘P or F1): every view, tab, page, Codex list, model and mode as a searchable list; pinned chats are listed first as "Chat: <title>" and open that chat; it also opens tasks, meetings and wiki pages by title, with the last five opened there first; a query also ends the list with a "See all N results" row (tasks and notes, meetings, wiki and jobs matching the query, under the Show filter) that opens Search with the query filled in
- **Theme**: the color icon in the status bar cycles Graphite, Dark Modern and Light. With nothing chosen the page
  follows the system setting; `?theme=light` in the URL picks one

## Phone

At max-width 480px (900px where noted) the app is one column with a tab bar. Task-specific phone behaviour (the + button, quick-add sheet, date sheet, Select) is under Tasks; sharing into the app is under [Share to the app (Android)](#layout).

- **Tabs**: a quick sideways swipe moves between the Codex, Chat, Sessions and Agents tabs (inside Codex the Lists drawer opens only from its button), and the new tab slides in from its side. The tab bar shows a count only on Chat (waiting); Codex (Needs you rows plus Reply queue rows), Sessions (chats elsewhere that are Done or Need you) and Agents (agents running in the chat on screen) show a dot. Every badge reads one count store (`appCounts` in `shared/counts.ts`, mirrored on Android), so the tab dots, the activity bar, the status bar, Overview and the MCP numbers agree
- **Bottom bar**: at max-width 900px the tab bar is a floating pill with a filled pill on the selected tab, and the chat composer is a pill row: + on the left (Add files, Use an MCP server, Model and mode with the current mode text), the text in the middle (the pill becomes a rounded box above one line) and a mic while empty (while it listens it pulses, on the phone with the voice level, and a tap stops it), Send once there is text, or Stop while running. While you compose in Chat the tab bar slides away, from focusing the field until you blur it with an empty message or close the keyboard on an empty one; a draft keeps it hidden, and the other tabs always show it. On a window without touch there is no keyboard signal, so the bar stays hidden from focus to blur. The rule is `barState` in `shared/bottomBar.ts` (`BottomBarLogic.kt` on Android). The Android app has the same bar and composer; its + sheet holds Photo, Take photo, Choose file, Use an MCP server (chips above the field, appended as "Use the ... for this."), Chat settings and the context percent (a tap sends `/compact` while the chat is idle), and a row above the field offers the rest of an earlier prompt. The empty-field hints come from `composerPlaceholder` in `shared/composerText.ts`, with shorter texts for the web pill composer so they fit one line at 390px
- **Installing on the phone**: `bun run native` tests and builds the native app, copies it to `dist/AgentView.apk` (served at `/api/app.apk`) and prints its path; `bun run native -- <adb serial>` also installs it
- **Launcher badge**: the launcher icon shows the Needs you count, the list plus the Reply queue rows (up to 99), when the phone build has the badge plugin, and nothing on the web
- **Haptics**: a swipe action, a task completion, a long press, a pull refresh and a drag drop give a short native tap in the phone app, and fall back to the WebView vibration; the web and desktop give none (see Row density in the design system)
- **Sync**: the interval sync runs only while the app is visible
- **Offline badge**: an Offline and reconnecting badge shows after 2 s without the stream and hides on reconnect
- **Load errors**: a page that cannot load, and a phone write that fails, say "Can't reach the Mac" for a dropped link and "The Mac took too long to answer" for a timeout, with Retry where the page had it; the server's own error text shows as is (`loadErrorText` in `shared/loadError.ts`, `net/LoadError.kt`). Web reads give up when the reply has not started within 20 s (70 s for Ops reads and a run's diff, whose gh and MCP calls take up to 60 s); writes have no timeout
- **Bottom-sheet menus**: a Menu opens as a bottom sheet at max-width 480px. A long press of 500ms on a row with a More menu opens it with a haptic tap; the kebab stays
- **Swipe undo**: every row swipe that completes, snoozes, moves, deletes, pins or archives shows one snack with Undo for 5 s; a newer swipe replaces it, so only the latest can be undone
- **Chat actions**: a chat row in Sessions swipes right to Pin or Unpin and left to Archive, with Undo; a running or waiting chat only swipes right, and a chat with no session id yet does not swipe. The native Sessions rows swipe the same way (pin snack "Pinned" or "Unpinned"), and not in read-only mode
- **Section headers**: grouped Section headers on Overview (Today), Tasks and Meetings stick to the top while the list scrolls
- **Pull to refresh**: at max-width 900px, pulling down 64px at the top of Overview, Tasks, Meetings, Wiki or Jobs syncs
- **Scroll restore**: Back from a task or meeting returns the list to its scroll position, kept per list and profile filter (Tasks and Meetings)
- **Edge swipe back**: at max-width 900px, a right swipe of at least 70px from within 20px of the left edge closes the open page or sheet like Back. It does nothing on a list or inside a Row swipe, and is off in the Android app (Android 10 or later), where system gesture navigation owns the edge
- **Keyboard inset**: `--kb-inset` holds the keyboard height (from 100px), so the New task and date sheets sit above the keyboard and the task page scrolls the focused field into view
- **Meeting actions**: an open meeting action swipes right for Done and left to Not mine
- **Phone alarm**: `mcp__agentview__phone_alarm` (time HH:MM, optional day within the next 7 days and label; no approval prompt, for Claude and Codex) sets an alarm in the phone's clock app. The server sends it to the one native app stream (`client=phone`, not read-only) that opened last, and a phone browser tab is never picked; with none it answers "No phone connected". In the foreground the app fires `ACTION_SET_ALARM` at once (a day other than the next time it comes round repeats weekly on that weekday); in the background it posts a "Set alarm 07:30" notification and the alarm is set when the user taps it. A read-only app does nothing, so the call ends after 20 s. The transcript shows the call as an Alarm card (time, label, status) that stays visible when the turn's work is folded, with See alarms on Android.
- **Touch targets**: Rows, Section actions and Chips are 44px high at max-width 480px and on coarse pointers; the done buttons on Overview rows, Related chips and Remove goal have full-size tap targets

## Codex

Codex lists Search, Overview, Tasks, Meetings, Wiki, Jobs, a grey Planning label and Goals (Slack summary is reached from Overview and the palette) for the work profile, the personal profile or both. On the desktop the list is the sidebar, on the web phone and Android a Lists button at the start of the header opens it as a drawer (Android: no edge swipe, a scrim tap or system back closes it). Each row is an icon, a label and a count (web: Tasks and Wiki; Android: the pending Wiki claim proposals); the active row has the neutral hover fill. The footer at the bottom of the nav holds the Show control (All, Work, Personal) and, except in the Android drawer, the sync line. Search and Goals are root pages like the others. Every root page has one header: Lists, a one-line title, the profile label as muted text after it when Show is not All, then at most one search field and two controls (a primary action, then More when it has items). Under the
nav, the sync line says when the app last synced with the hub, how many changes still wait for the hub, and "Not saved on this device" when the local copy cannot be written. While the hub cannot be reached, the banner above the list (on the phone "Can't reach the hub" with Retry) says how old the shown data is, such as "Last synced 14:20" or "Last synced yesterday 14:20" (`syncedAt` in `shared/syncText.ts`). While the hub skips its Slack, Gmail or calendar scan because
that Claude account is at its usage limit, a line below it names the paused scans and the time the limit ends.
When everything is healthy that one line is all the nav shows; clicking it syncs and shows the scan lines. When a scan failed, stalled or is paused, one small
line per source appears below it with the last Slack, Gmail and calendar run, its counts, the error in the warning color,
or "not set up"; Slack and Gmail have a "Scan now" button.

### Overview

- Overview is headed by a greeting in the reading serif after an accent spark, like the Claude apps' home ("Good morning, Tue 24" on web, "Good morning" on the phone). An event on both the work and personal calendars shows once under All
- Overview shows three blocks, each hidden when empty: Up next, Needs you and Today. While data loads it shows a skeleton
- Calm by default (24 Nov 2026): Today shows 5 rows then Show all N; Done today is one row ("N · last: <title>") that expands to the finished chats; Ideas show only when nothing is overdue or due today; Plan my day is offered only before noon; two or more weekly goals fold into one "Goals this week" row ("At risk · 1 of 3 done", `goalsLine`) that opens the goals page, and a single goal shows as its own row
- Phone dictation (25 Nov 2026): the composer mic, the Talk button and the Codex ask bar keep listening through pauses until tapped again, using a segmented on-device session on Android 13+ (network recognizer when the language pack is missing; older phones stop at the first pause). A stop that gets no answer in 2 s, or a second tap, cancels and makes a fresh recognizer so the mic always starts again (`Voice.kt`, `Heard`)
- Up next is one card. It is the next meeting today that has not ended (a running meeting counts, at any time today): title, one meta line (a countdown, then time, room, N people; "Starts in 30 min" before the start, "Ends in 20 min" while it runs, "Starts now" under a minute), a Live badge while it runs, a More menu (web and phone) with Prep (not on a solo meeting; it asks today's Codex chat "Prepare me for ..." via `prepText` in `codex/AskBar.tsx` and `codex/CodexAsk.kt`, `shared/fixtures/prep-text.json`; the phone hides it in read-only mode), Open calendar (when the meeting has a link) and Notes (opens the meeting page with the notes field in edit mode); tapping the card opens the meeting. With no meeting left today it is the first open task due today by due time, with a tinted Done button (Undo in the snack) and its title opening the task; overdue tasks never fill it. With neither, one "Nothing today" empty state names the next meeting or dated task on the same line ("Nothing today. Next: <when> <title>") and a New task button; adding a task for today replaces it with the card
- Needs you is one row with a count badge and a chevron, shown only when the count is above zero. The count is the Needs you list plus the Reply queue rows. The row opens a bottom sheet headed Needs you with the total, then Tasks, Asks and Replies, each with its own count (a group with no rows is left out; the total ignores the older-than-3-days filter); Esc, the scrim, a drag down and the back gesture close it and focus returns to the row, and it closes by itself when the count reaches zero. From 901px wide it opens as a centred dialog instead of a bottom sheet. Rows carry no badge (Overdue and At risk lead the meta line); a DM or Slack row has no X, its More menu ends with Nothing asked and Dismiss and a left swipe dismisses it with Undo. Dismiss syncs across devices: a dismissed DM stops waiting until its next message, and a dismissed bullet is stored on its Slack summary. Nothing asked (also on asks, with Dismiss or Not mine after it) is the manual triage for an FYI: an ask becomes a note, a DM or Slack bullet is saved as a note in Wiki > Notes and the row leaves the sheet at once, with a "Saved as a note" snack and Undo; a failed write keeps the row and says so, and it is disabled in read-only mode on the phone. Tasks holds overdue and at-risk tasks and the open actions of meetings that ended in the last two hours; Asks holds asks and promises to confirm, Slack DMs waiting on me, the latest Slack summary's "Needs you" bullets, "<job> failed" rows for each enabled job whose newest run ended in error in the last 24 hours and is not queued (meta: the first line of the run's output and its age; a tap opens the job, Run again queues it and takes the row out), each once (three or more overdue collapse into one row with Move N overdue to today in the Tasks header), "Just ended · title" rows with Copy follow-up and Notes in the More menu, one row "N asks older than 3 days" that filters the Reply queue to them, and one row "N wiki claims wait for you" that opens the claim review; each group shows 5 rows then Show all N
- Running is a Section with a count and one grouped list of the chats that run or wait on me (waiting first; a chat waits when its header says Needs you or its run needs you, and a stalled chat is neither), shown between Needs you and Today and hidden when none does. A row is the chat title, the folder and what it does (the status line, or Waiting for you), a Running or Needs you badge; tapping opens the chat. The phone keeps the rows of the last sync on the device and shows them at once on open, then pulls only what changed
- Today is a Section and one grouped list of the rest of today's meetings and the open tasks due today or overdue, overdue first, then in time order; a task already in Up next or in Needs you as at risk is left out. A meeting row is its title and time, with a Live badge while it runs, and opens the meeting; in the 10 minutes before the start, a meeting with a link shows "Starts in N min" and a filled Join button that opens the link (a new tab on web), on web and the phone. A task row is its title and due time (a Late badge when overdue), a check button (Done with Undo) and a More menu (Snooze to tomorrow with Undo, Open). Seven rows show, then Show all N expands the list in place. Once a task is done today the header also shows a quiet "N of M done" badge, M being N plus the open tasks due today or overdue (at-risk ones included, meetings not)
- The Overview ask bar is one input line with mic and send while idle; the recipe chip (Prep next meeting within an hour of one, Draft my weekly update on Thursday and Friday afternoons, otherwise Plan my day, What's next or Wrap up my day) appears on focus, and the Task/Ask, profile and When? chips appear once there is text. A personal ask also sends my personal meetings from today to three days ahead and asks the chat to suggest alternatives and change the calendar only after confirmation
- Summary page (not in the nav; reached from a Slack row in Needs you and the palette): a TickTick-style report with Date (Today, This week, Last week, This month) and Status (All, Completed, Not completed) rows, Completed and Not completed Sections of task Rows (day as meta) that open the task, and a Copy button for Markdown; below it a link to the Slack asks to review; chats with a summary in the range grouped into DMs, Mentions and Channels Sections, 5 rows each then Show all N; the Sonnet summary folded to 8 lines; and Summarize.
- Replies (the Reply queue, in the Needs you sheet): every Slack and Gmail ask (a suggested row from either scan, never a You said promise) shows here once and not in Up next, Today or Tasks. Each ask is one row: the title, then person and age (Snoozed or FAQ after it), the quote clamped to 1 line (left out when empty; the text before any checklist), a status line (Needs you badge when tagged needs-you, else Reply ready when a draft exists, else No draft, which is hidden when the ask has steps), one line per step (done steps muted with a check, waiting steps in body colour), and the draft clamped to 2 lines. One primary button: Send for a Slack ask with a draft, Approve (sends the draft the same way) when that ask is tagged needs-you, Open (the source link) for everything else, Gmail included. The More menu lists Edit draft and History (Slack with a draft), Open thread (when the primary is not Open), Done (closes it, sends nothing, keeps the draft, the scan does not re-suggest it), Make task (an open undated task in Today), Snooze: In 1 hour, Later today 16:00 until 15:00, Next workday 09:00, Ask Claude and Skip (a Slack ask is closed with its draft dropped; a Gmail ask is dismissed with Undo). On the phone Send, Approve, Done, Make task, Snooze and Skip are off in read-only mode. A snoozed ask leaves the queue and every count until its time passes (synced across devices, one Undo), then returns in queue order with "Snoozed" after its age. History shows the last 3 replies sent to that person (date and first line, newest first), loads when first opened and reloads after a reply to that person goes out. Send all FAQ answers and Copy access and limit requests sit in the section header. Asks older than 3 days also show as one row above the queue ("N asks older than 3 days", oldest age): tapping it filters the queue to them, with an Older than 3 days chip that clears the filter and Dismiss all N in place of the batch buttons. Dismiss all keeps the drafts, sends nothing and shows one Undo. On a desktop pointer an ask takes keys: j / k or arrows move between asks, Enter opens the task, s sends the draft, x skips (both ignored while that ask is busy), and focus moves to the next ask after one leaves; with nothing focused j or k focuses the first ask. ## Review findings

"Ask Claude to review" on a pull request and the inbox's review prompt run `/code-review <number>`. The findings
it reports show up in the pull request's pane, most severe first: a row opens the file on that line, Fix sends
the finding to the chat, Fix all (two or more findings) sends them all in one prompt, Dismiss hides it for good (kept per repo in `~/.agentview/findings.json`). "Review changes
with Claude" in the Changes view and "Review changes" in the chat menu (web and phone; off while Claude runs or when no file changed)
run `/code-review` on the working tree; those findings show at the bottom of the Changes view. The Findings header
reads the count, "Reviewed <since>" and Fix all (web and phone). On the phone a working-tree finding opens the file as text,
scrolled to its line (the last line when it is past the end) and tinted for 1.6 s; read-only mode hides Fix, Fix all and Dismiss.

In the web Changes view ⌘-click (Ctrl-click) toggles a file into a selection and Shift-click picks a range within
one section. Discard, Stage and Unstage on a selected row then act on every selected file in that section; Esc
and any git action clear the selection. The phone has no multi-select.

`/spec-review` reports under the target `spec:<slug>`. A repeat review replaces the list and keeps dismissed findings hidden.

A failed check in the web pull request pane has a Fix with Claude button. It starts a new chat in the local checkout or
worktree of the PR's branch (the repo root when none has it, which the prompt says) with the check name, the last 80
lines of its `gh run view --log-failed` log and the instruction to fix it, run the checks and not push.

A pull request Claude opened with `gh pr create` stays linked to its chat: the pull request row shows "Open chat"
while that chat is open.

Merge when checks pass is a per-PR switch in the pull request pane (web Row, phone More menu), off until you turn it on
and confirm. The server (`integrations/automerge.ts`, entries in `~/.agentview/automerge.json`) checks each armed PR every
60 s and runs `gh pr merge --match-head-commit <head>` once nothing is draft, conflicting or waiting for review, no check
failed or is pending and at least one check passed. A new commit or a re-run is picked up by the next poll. The row shows
why it waits, a merge posts "Merged in <repo>", and a failed merge posts "Auto-merge failed" and stops until you turn it on again.

## Context

The meter shows the tokens in context and turns red past 200k, or past 80% of the model's context window when the agent
reports one (Codex does). AgentView then compacts the conversation when the turn ends.
A failed compact is retried once the context has grown by another 20k tokens.

## Notifications

When a chat asks a question, needs a permission or finishes a turn, AgentView notifies you. On the Mac the server
shows a system notification with a sound if no window is viewing that chat, at most one per chat every 30 seconds;
clicking it opens that chat in the browser (a GitHub item opens the Sessions view).
The browser shows its own notification while the tab is hidden; clicking it opens the chat. The bell in the status
bar turns browser notifications on or off.

On the phone and in the browser, a chat that stops running notifies "<Provider> finished in <repo>" with the reply's first line as the body (the chat title as the phone's sub text, the first body line on web; the title alone when there is no reply line), and "<Provider> failed in <repo>" when it failed. A chat with an active run (tries or a job) never gets the Finished notice: the run reports when it ends. Muted chats skip Finished notices. The rule is `chatNotices` in `shared/notices.ts` with `shared/fixtures/chat-notices.json`, mirrored in `chatNotice` in `app/ExtrasLogic.kt`.

On the phone, a chat that asks one single-select question notifies with the question as the body and the options listed as "1. <label>" in the expanded text. With two options each is an action button next to Reply (label clipped to 20 characters); with more, only Reply shows, and a reply that is an option number or a label (any case) answers with that label, other text goes as free text. A tap on a question that is no longer open says "Already answered". Multi-question and multi-select asks keep the plain notice.

On the phone, an approval for Edit, Write or MultiEdit shows the file name and "+N -M" in the title and the first 8 changed lines (prefixed + or -) in the expanded text, so you can decide from the shade.

For a phone in the background, the same notifications can go to an [ntfy](https://ntfy.sh) topic. Push is off
until you set `AGENTVIEW_NTFY`, or `ntfy` in `~/.agentview/observe.json`, to a topic name or a full URL on your own
server, then subscribe to it in the ntfy app. Tapping the push opens the chat. At 08:00 the server sends one "Overnight: N runs, M need you" push listing each try or job that ended or got a round since 20:00 the evening before (last round line or end note, cost, needs you) and opens the Sessions view; it sends nothing when no run qualifies. The assistant hub uses the same topic for meeting and task reminders and the 08:00 morning brief; it sends no reminders from 17:00 to 08:00, and tasks that fell due overnight go out with the first morning check, as does the nudge for a transcript that landed overnight. Tasks of one profile that come due in the same check go out as one "N work tasks due" (or personal) push (first 5 titles, then "+N more") with no Done or Snooze; a single due task keeps Done and Snooze. A meeting gets a heads-up only when there is something to prep (open actions of yours from the previous one, its decisions or open questions, or a calendar link); one that started up to 5 minutes ago still gets it ("starts now"), so an 08:00 meeting is covered. A job run pushes only when it fails or when the job's prompt asks for a push; a successful report shows in the Context fold only. Open tasks roll to today each day (a rolled evening task is caught up on weekday mornings only), but only weekday rolls count toward sending a task back to review after 3.
Urgent Slack and Gmail asks that arrive while a calendar meeting runs (not all-day events, time blocks or
events with no other attendees) are held; an ask the scan marks urgent goes out during the meeting anyway. Within a minute
after it ends, up to 3 held asks go out one by one with their own Open, Send reply and Skip, more as one push "N urgent while
you were in <meeting>". Asks you accepted
or dismissed meanwhile are left out, and a queued push for an ask you already reviewed is dropped.

A chat that runs for 15 minutes without sending anything is reported once the same way and gets a slow yellow dot
in the chat list until its next message.

## Plan and spec

Two ways to have a change built, lightest first:

- **Plan first** (permission mode Plan, or Start as Plan first on the phone): Claude writes a plan and waits in plan mode; approving it lets Claude build in the same chat. For a change small enough to read as one plan.
- **Start with a spec** (palette "Chat: Start with a spec"): Claude writes `.claude/specs/<slug>.md` with Requirements, Design and `- [ ]` Tasks, then stops. Open the file to see its Tasks header and Start one task at a time. For work you steer task by task.

## Personal and work Claude accounts

`./claude-alt.sh` sets up `~/.claude-alt` for a work Claude login and `./claude-alt.sh 2` sets up `~/.claude-alt2` for a third
account, next to the personal one in `~/.claude`. Each shares settings, skills, plugins and chat history with `~/.claude` and keeps its own
login; log in once with `CLAUDE_CONFIG_DIR=<dir> claude` and `/login`. A new chat under the `personalRoot` folder starts on
Personal and any other folder on Work; a reopened chat goes back to the account it was last on. Codex questions go to a daily
chat per profile: work ones run in `~/.agentview/codex-work`, so they get the Work account and the work wiki and data, and
personal ones in this repo. When a turn ends on a usage limit, the chat moves to the next
logged-in account with usage left (the main account, then the second; the third is picked by hand only) and continues where it stopped, and new chats start
there until the limit resets. The composer menu shows the account (Account 1 to 3 unless `accountLabels` in `~/.agentview/settings.json` names them) and switches it by hand. The status bar shows the account with
its weekly and 5-hour usage as `w25 h15` (read when a turn ends, every 10 minutes while the chat is open, and on a click while a Claude process is open), and the even weekly pace (100/7 % a day, to the hour) on hover. When the
week is ahead of that pace or either window passes 80%, it turns yellow and a click switches the chat to the other
account. A switch restarts the Claude process, so Claude recreates the chat's scheduled jobs in the new one.
Only the CLI's own usage-limit notice counts as a limit, so a reply that mentions a rate limit does not switch.
Before a new chat starts, a limit mark is checked against the account's live usage, at most every 5 minutes and
without sending a prompt. The mark is cleared when the 5-hour and weekly windows are under 100% and no per-model
weekly window is full; a failed check keeps it.

## Runs

Every `/tries` and every coding job of the hub ([autopilot.md](autopilot.md)) is a run, kept in the host in
`~/.agentview/runs.json` (active runs and the latest 100 ended ones, each with its last 50 rounds) and served at
`GET /api/runs`. A round is the outcome of one turn, its one-line summary and its cost. Each try's prompt tells Claude
to answer first in plain sentences and finish the reply with `ROUND: <done|progress|blocked|question|nothing> <one sentence>`;
the line is read by the server and hidden from the transcript, the chat row and push bodies. A round without the line
counts as progress. A run that ends pushes "Tries ended in <repo>" or "Job ended in <repo>" with its reason, unless you
stopped it or the chat is open. A pending approval marks the run paused until the answer.

`/build [auto] [until HH:MM] <request or spec path>` is a build run in its own chat (`shared/build.ts`, `session/build.ts`):
a request first gets a spec with a Goal line, then each unchecked task runs in a fresh context (`/clear`, then a brief)
that makes the change, runs the checks, commits without pushing, ticks the box and adds to `<slug>.notes.md`. Without
auto the run pauses for "Build all" after the spec and for you on a blocked task; with auto a blocked task becomes `[~]`
and the run goes on. With until it asks for 1 to 3 more tasks for the goal when the list runs out, until that time or two
searches find nothing. It ends with a recap at the stop time, at 60% weekly usage or when the tasks are done; Pause
takes effect after the current task. Build all on a spec's Tasks header, Start as Build on the New chat sheet and the
MCP tool `start_build` (any chat; it opens a new chat in the project) start one.

On the web a chat's run heads its Agents rail (`RailHead`), on Android its Agents sheet (`RunActions` and `RunRows` in
`RunsUi.kt`): tries show Open board and Stop, jobs Stop, and with no run the header has Stop all agents. Under the state
line ("Tries · 3 chats", "Job · <branch>", "Paused · <why>") come the Now row, the agent's latest status or the last round
("Round 4 · 02:10 · progress: merged X"), whichever is newer, with its meta from `nowMeta` in `sessions/runLogic.ts` and
`RunsLogic.kt` (`shared/fixtures/now-meta.json`: the status time, "Next: ...", the steps left), and the run's what text
with the total cost. The running agents stay in the Agents pane below. The controls take a run id, so they work from
any screen. The chat header (Android) and the web status bar read "Running · 2 agents" while agents run with no turn and
"Idle" only with no run and no agent.

A run needs you while its last round is blocked or a question, or it is paused for your approval, until a later round
or a message from you in that chat (the server decides this, so web and phone agree). There is no separate list of runs:
a run shows in its chat's run head, and a hub job's failed runs on its job page. A coding job's
run that waits for review shows its review card in place of the run head in the Agents rail (web) and above the composer of its chat (phone): the summary row
(last round, branch, size and age) with Needs you, the first 3 changed files with Show all, and Commit, push and open a
PR with Approve (behind a confirm) and a More menu with Revise… and Discard. Sessions and Open chats rows of a chat with
an active run show the run tag ("Paused" in warn, else the sync icon) or "Needs you" in warn. The status bar shows "N running"
and "· M need you" in warn while a chat runs or waits on you (the Overview Running counts), and a click opens Sessions.

## Travel

Travel is a page (activity bar briefcase, the phone More sheet, "View: Travel" in the palette, `?page=travel`) for trips, work or leisure. The list shows trips (current first, then upcoming, then undated; past trips sit in a collapsed Archived section below, newest first, derived from the dates) as hairline cards (web and Android, one column on a phone): the first image receipt as cover, else a briefcase strip, the name, dates, receipt count, totals and "From calendar" for found ones, and the state (Now in accent, In N days, Past) as a chip (`tripCard`); New trip asks for a name and From / To dates. On the phone a capture row (Take photo, Photo, PDF / file) sits above Trips; on desktop the list header has Take photo and Add files. A receipt added from the list is read by Claude (Haiku) while the list shows "Adding N receipts…", then auto-filed under the trip whose dates include the receipt date, else the current trip, else the nearest trip (`fileTrip`), and a notice names the trip; with no trips the server refuses it ("Add a trip first"), so the empty page (web and Android) shows one line, Find in calendar and New trip, and the capture row; a receipt picked there opens New trip and is filed under the trip once it is saved. Find in calendar (next to New trip, in the empty state, and the calendar icon in the phone header) sends the hub's calendar events from 30 days back to 120 ahead to Claude (Sonnet, work account, no tools), which groups flights, trains, hotels and events away from home into trips with a name, dates and a plan of dated items (kind, times, title, place, booking number); a notice says what was added or updated (`scanText`). A found trip follows the calendar on the next Find until you edit it, and when it takes a new plan its notes are cleared (they came from the scan); a trip you made gets the found plan only while its own is empty; a deleted found trip's dates are kept so it is not found again; a found trip that already ended is skipped, one that overlaps an archived trip updates it and returns it to the list, and a trip that ended in the 30-day window and was never found is added with New trip (`mergeTrips` in `shared/travel.ts`, `POST /api/travel/scan`). A trip page shows the name with its dates and state ("Now" with an accent dot), the capture row (desktop: Take photo and Add files; a trip-page upload is filed under that trip at once and read in the background), the Itinerary, its receipts newest first (thumbnail or file icon, merchant, date, category, amount), the total per currency and a Notes field for booking codes and addresses. A Checklist section (open items counted) sits between the Itinerary and the receipts and shows only when it has items: a tap ticks an item (`POST /api/travel/check` flips that one item, so items the travel tool added meanwhile stay, and it does not freeze a calendar trip), and nothing adds items by hand. The Itinerary lists one group per day (weekday, "Today") with start and end times in one column, a kind icon, the title and "booking · place"; on a current trip the next timed item is highlighted (`nextItem`). A tap opens a sheet to edit or delete an item, and Add item adds one by hand; an item save sends the whole plan, so a scan and a second device writing at once are last write wins. Old trips keep their text notes and show "No plan yet". Its More menu has Ask Claude (hidden on a read-only phone), which sends a pre-trip brief prompt (`tripAsk`: getting to the airport, readiness, packing and weather, open items; the work chat for a trip whose name or event titles hold a work word, `tripKind`) to the Codex chat, and Home address, which saves the start address the brief uses (`TravelData.home`, `POST /api/travel/home`); the brief also offers to set a wake-up or leave-home alarm on the phone with `mcp__agentview__phone_alarm`; what is settled in that chat is written back to the trip with `mcp__agentview__travel` (notes, plan items, checklist, home) and shows when Travel is opened again. The menu also has Edit trip, Export receipts (CSV), Copy summary and Delete trip (asks first, deletes the files too).

An added receipt is saved on the server Mac in `~/.agentview/travel` (`travel.json` and `files/`) and Claude (Haiku, work account, no tools) reads an image or PDF (in the background under a trip, awaited when auto-filing, up to 90 s) to fill in merchant, amount, currency, date and category; a field the user typed meanwhile wins. The row says "Reading…" while it runs and the page polls every 2.5 s; a read still pending after 5 minutes shows as failed. A tap on a receipt opens a sheet with the picture (or Open for a PDF) and the fields to correct, Save and Delete. On the phone, Take photo in Travel opens Google's document scanner (ML Kit, as in Drive: edge detection, crop, straighten, cleanup filters, gallery import), falling back to the camera when Play services lacks it. The web scales photos to 2000px and the phone to 2048px before upload. Routes are `/api/travel*` (`server/src/http/travelRoutes.ts`); shared logic in `shared/travel.ts` and `travel/TravelLogic.kt`, with cases in `shared/fixtures/travel.json`.

## Sketches

`/sketch <what>` (Claude and Codex chats; with no text it sketches the screen being discussed) asks the agent for one self-contained HTML mockup in `.claude/sketches/<name>.html`: inline CSS, no scripts, no external URLs, both themes under `html[data-theme]`, working at 390px and 1280px. The user's message keeps the typed `/sketch` text. The Sketches page (activity bar paint can icon, the phone More sheet, `?page=sketches` or "View: Sketches" in the palette) lists the regular `.html` files directly in that folder of the open chat (no symlinks or folders), newest first, as a grid of hairline cards (web: a 1280 by 800 preview in an `<iframe sandbox="">` scaled to the card, loaded only when the card scrolls into view, then the name and age), five cards then "Show all N"; with none it shows "No sketches yet" and a New sketch button that puts `/sketch ` in the composer. A tap opens the sketch: Back, the name, Desktop / Phone and Light / Dark chips and a menu with Open file, Copy path, Copy relative path and Copy name. The page opens only names the list returned. The sketch runs in an `<iframe sandbox="">` (no scripts, no access to the app) whose `srcdoc` is `sketchDoc` from `shared/sketches.ts`: a Content-Security-Policy meta that blocks every load but inline styles and data images, `<base target="_blank">`, meta refresh removed and the chosen `data-theme` on `<html>`, with cases in `shared/fixtures/sketch-doc.json`. Desktop is 1280 by 800 scaled down to the pane, Phone 390 by 844 scaled to fit; a rewrite by the agent reloads the open frame. A file over 1 MB is not shown. A chat shows a sketch card (paint can icon, the name, "Sketch written" or "Sketch edited · +N -M") for a successful write to a `.claude/sketches/<name>.html` file; a tap opens the page on it. The native Android app has the same page and card (More sheet, `?page=sketches&slug=<file name>`), with Phone first and a menu with the three copy items only: the sketch runs in a WebView with JavaScript, network, file and content access off and link taps ignored, the page built by a Kotlin port of `sketchDoc` run against the same fixture; Desktop asks for a 1280px viewport. New sketch is refused in a read-only run.

## Keyboard and screen readers

- A screen reader hears when Claude finishes a turn (its last reply, or the error it stopped on) and when it asks a
  question or for a permission, not every streamed word
- Answering a question or permission card moves focus to the next card, or to the composer after the last one
- The composer is labeled and its suggestion list is a listbox. The command palette, the file picker and the other
  pickers (repo, model, saved prompts) list results as listboxes; closing a picker or a confirm dialog returns focus
  to where it was
- Transcript steps, open editors, Source Control rows, terminal tabs and the collapsible sections in the ops panes open
  with Enter or Space. The file tree is a tree: arrow keys move, Right and Left open and close folders, Enter opens
- Errors and deploy progress in the Observe, Deploy, GitHub and MCP panes are announced; closing a detail there
  returns focus to the list
- In Codex, snack messages are announced, with "Undo available" when they have Undo. Goals, Related
  and the Slack DMs under Since <meeting> are lists, and Esc in a goal field restores its text

- Codex lists share design tokens in tokens.css: `--row-h` (40px), `--row-title` and `--row-meta` (md and sm type), `--meta-fg` (muted secondary text) and `--hairline` (1px separators). Task rows, section headers with counts and the Slack Summary page use them.
- On the web and Android Overview every group (Up next, Needs you, Running chats, Today, Plan your day, Goals, the morning card) is a hairline card: `--hairline` border, `--shape-lg` radius and `--surface` fill, the same shell as the design system Card (Android: `LocalCardGroups` switches `Group` to it).
- On the web and Android Tasks lists each section's rows (Overdue, the days, Review, Done, search hits) sit in the same hairline card, with the section label above it.

## Copy a file path

Copy path, Copy relative path (left out for a path outside the chat's folder) and Copy name copy a file's path with `pathCopies` (`web/src/workspace/copyPathLogic.ts`, `FilesLogic.kt`, cases in `shared/fixtures/copy-path.json`) and show "Path copied", "Relative path copied" or "Name copied" (web adds "Copy failed"). On web a right-click on an Explorer row or a file link in a chat reply opens them at the pointer (`CopyPathMenu`; a bottom sheet at phone widths, where a long press on an Explorer row opens it too), and the More menu of a chat file or doc card and of a sketch lists them. On Android a long press on a Files row or a chat file or doc card opens them as a dropdown, and the Sketches More menu lists them; inline links in a reply have none. Copying writes nothing to the server, so it works in read-only runs.
